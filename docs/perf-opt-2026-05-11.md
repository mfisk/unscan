## Bottleneck Analysis

### 1. FreeType Library::init() + Face creation per SSIM rerank call
**Location:** `verify.rs` → `render_via_freetype()`  
**Impact:** HIGH (~30-40% of runtime)

Every call to `render_via_freetype()` does:
```rust
let lib = Library::init().ok()?;                          // ~100µs: loads FT library
let ft_face = lib.new_memory_face2(font_data.to_vec(), 0); // ~200µs: clones 200KB + parses font
```

With ~7 avg rerank candidates × 94 lines × 2 render scales = **~1,300 calls**.
Each call: ~300µs overhead → **~390ms just in FT init overhead**, plus the
`font_data.to_vec()` copies ~200KB × 1,300 = **260 MB of unnecessary allocation**.

**Fix:** Thread-local `freetype::Library`, avoid font_data clone.

### 2. Redundant SSIM verification in Pass 2
**Location:** `main.rs` Pass 2 decision matrix  
**Impact:** HIGH (~15-25% of runtime)

The SSIM reranking in `match_font()` already computes and returns the SSIM score
as `FontMatchResult.score`. Then Pass 2 calls `verify::verify_text_region()` AGAIN:

```rust
if !keep_raster && !args.no_verify {
    let (score, _dy) = verify::verify_text_region(...);  // REDUNDANT
```

This re-renders text via FreeType + recomputes SSIM for every vectorized line.
For 32 vectorized lines × 2 scales × (FT render + SSIM): **~6,400 SSIM evaluations wasted**.

**Fix:** Add `ssim_verified` flag to `FontMatchResult`; skip Pass 2 verify when true.

### 3. 25 full image copies in vertical shift search
**Location:** `verify.rs` → `ssim_windowed_best_vshift()`  
**Impact:** MEDIUM (~10% of runtime)

Each of 25 shifts creates a full `GrayImage` copy of the rendered line region
(~800×40 px = 32KB per copy). With ~1,300 SSIM calls × 25 shifts = **32,500
image allocations** totaling ~1 GB of transient allocation.

**Fix:** Pass shift offset into SSIM kernel, adjust y coordinates on the fly.

### 4. Double-pass per SSIM window
**Location:** `verify.rs` → `ssim_windowed()`  
**Impact:** MEDIUM (~5-10% of runtime)

Each 11×11 window is scanned twice: once for ink counting, once for weighted
statistics. 66,750 SSIM evaluations × ~200 windows each × 2 passes × 121 pixels
= **3.2 billion redundant pixel reads**.

**Fix:** Single-pass accumulation of ink count + weighted statistics.

### 5. font_data clone into FontMatchResult
**Location:** `font_match.rs` lines ~500, ~510  
**Impact:** LOW-MEDIUM (~3-5%)

`entry.data.clone()` copies ~200KB per winning font. For 94 lines: ~18 MB of
unnecessary allocation. Then cloned again in paragraph grouping.

**Fix:** Use `Arc<Vec<u8>>` or entry index.

## Implemented Optimizations

1. **Skip redundant Pass 2 SSIM** — `ssim_verified` flag on FontMatchResult
2. **Offset-based vertical shifts** — no image copies in vshift search  
3. **Single-pass SSIM windows** — combined ink check + stats computation
4. **Thread-local FreeType Library** — cached across calls within a thread
5. **Early termination in shift search** — stop at SSIM ≥ 0.92, search center-outward
